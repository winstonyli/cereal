# One front-end builtin table (CLEANUP_PLAN AR1, option s1)

Decided 2026-11-04 (v1): fold the per-name facts the checker keeps beside `cbuiltin_tab.h`
into that table as columns. `BI_ROWS` (back-end built-ins) and `ev_host_fn` stay as they are
(option s2, parked in `PARKED.md`).

## Why

`cbuiltin_tab.h` (1062 rows, generated from gcc's diagnostics) answers "is NAME a built-in,
and what is its type". Three more tables answer other questions about the same names and are
kept in sync with it by hand or by separate probes:

| Table | Where | Size | Question |
|---|---|---|---|
| `cbuiltin_pure.h` | generated by `bench/tools/gen_pure_builtins.py` | 560 names | is a call side-effect free (`call_pure`) |
| `builtin_nonnull` | `src/c/ccall.c:15` | 75 rows + an `*_overflow` name pattern | which arguments are `nonnull` |
| `builtin_format_pos`, `builtin_scanf_pos`, `builtin_is_va` | `src/c/cformat.c` | 12 + 6 rows, a `v` prefix test | which argument is the format string |

The comment on `builtin_nonnull` says "probed from gcc itself", but no probe script exists in
the repo: that table has no regeneration path (checked: `bench/tools/`, `tools/`). Each lookup is
its own bisection or linear scan, repeated per call checked. All 560 pure names, the 6 scanf
names and 10 of 12 format names are rows of the tab already (measured 2026-11-04).

## Goal

One row per built-in name carries every per-name fact the front end reads. A caller does
`bt_find` once and reads columns. The three side tables, `pure_first_char`, the bisection in
`call_pure`, `builtin_is_va`'s prefix test and `gen_pure_builtins.py`'s separate output file go.

Non-goals: the back end's `BI_ROWS`, `ev_host_fn`, `std_names` (macros and types of the driver,
not built-ins; dropped from AR1), the `e_call` handlers (`choose_expr`, `shuffle`, tgmath),
`cbuiltin_x86.h` (target built-ins with their own lowering kind).

Anti-goal: a hand-edited column inside a generated file. Every new column has a generator and a
check that regenerating reproduces the file.

## Design

Row shape (`BTab`, `src/c/cexpr_int.h`) gains three fields:

- `pure`: 1 when gcc builds a call without side effects (today's `cbuiltin_pure` membership).
- `nonnull`: bit mask of 1-based argument positions (today's `builtin_nonnull`, which returns
  `uint64_t`; positions are at most 5 in the table).
- `fmt`: format-argument position (0: none) and a kind: printf, scanf or none. `va` (a
  `va_list` argument) is read from the signature, not from a name prefix: the row's `sig`
  spells it `__va_list_tag *` (checked: `vprintf`, `vsnprintf`). `strfmon` and `strftime`,
  special-cased by name at `ccall.c:1826`, become `fmt` rows too.

Generation: one script, `bench/tools/gen_builtin_attrs.py`, probes gcc for the three columns and
rewrites the tab's rows in place (the existing generators keep owning name/hdr/mismatch/sig/gnu).
`gen_pure_builtins.py` becomes a function of it. The header comment of `cbuiltin_tab.h` names the
column owners.

Callers:

- `call_pure` (`ccall.c`): `bt_find(c, name, spelled_with_prefix)` then `bt->pure`. The
  `ccall_is_builtin` guard (a plain name must also be a library built-in) is what `bt_find`'s
  `any` argument already encodes.
- `builtin_nonnull` callers (`ccall.c:567`, `:1818`): read `bt->nonnull`. The
  `{s,u}{add,sub,mul}{,l,ll}_overflow` pattern (`add_overflow` and friends are not rows of the
  tab today; checked) either becomes rows or stays one pattern in `bt_find`'s caller; the plan
  picks, because 24 generic-signature rows in a table of fixed `sig` strings may cost more than
  the pattern saves. Both `__builtin_`-only call sites (`ccall.c:567`, `:1818`) read the column.
- `builtin_format_pos`/`builtin_scanf_pos` callers (`cformat.c:1441`, `:1443`, `ccall.c:1825`):
  read `bt->fmt`.

Rows missing today (measured): the 12 `__*_chk` names of `builtin_nonnull`, and `dprintf`,
`vdprintf` of `builtin_format_pos`. The plan must check each against gcc and either add rows
(`gnu = 2`, `__builtin_` spelling only for the `_chk` names) or record why the entry is dead.

## Checks that can fail

1. Before deleting a side table: a throwaway program evaluating old function and new column on
   every name in the tab and on every name in the old tables, expecting equality; any difference
   is a finding (an entry that was wrong, or a spelling the new lookup misses).
2. Gate unchanged: `run`/`san` pass counts, verify 637/638, 289/289, 3908/3910, globals allowed.
3. Work count: callgrind instructions before and after (current 3,819,377,416; ICOUNT A/A first
   for the tolerance). `call_pure` runs on every call, so the count must not rise; a drop is
   expected from removing the first-character probe plus the second bisection.
4. Regeneration check: running `gen_builtin_attrs.py` twice leaves the file identical, and its
   output equals the committed tab (a script the gate can call, or a test).

## Decisions for the user

- **Nonnull provenance.** No probe exists. Options: write the probe (gcc's `-Wnonnull`
  diagnostic for a null literal in each position, per name; recommended: the column then has a
  regeneration path like the others) or seed the column from the current table once and mark it
  hand-owned with a check against gcc run on demand.
- **`std_names`.** Dropped from AR1 as a different domain. Confirm.

## Not decided here

Row storage order, field widths and the exact `fmt` encoding are the plan's, provided every
check above passes.
