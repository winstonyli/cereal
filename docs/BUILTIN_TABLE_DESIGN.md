# One front-end builtin table (CLEANUP_PLAN AR1, option s1)

Decided 2026-11-04 (v1): fold the per-name facts the checker keeps beside `cbuiltin_tab.h`
into that table as columns. `BI_ROWS` (back-end built-ins) and `ev_host_fn` stay as they are
(option s2, parked in `PARKED.md`). Reviewed once against the code by a Sonnet reader (round 1,
2026-11-04: six spec errors, one missed table, two behaviour differences, all folded in below).

## Why

`cbuiltin_tab.h` (1062 rows, generated from gcc's diagnostics) answers "is NAME a built-in,
and what is its type". Other tables answer further questions about the same names and are kept
in sync with it by hand or by separate probes:

| Table | Where | Size | Question |
|---|---|---|---|
| `cbuiltin_pure.h` | generated by `bench/tools/gen_pure_builtins.py` | 560 names, all tab rows | is a call side-effect free (`call_pure`) |
| `builtin_nonnull` | `src/c/ccall.c:15` | 75 rows + an `*_overflow` name pattern | which arguments are `nonnull` |
| `builtin_format_pos`, `builtin_scanf_pos`, `builtin_is_va` | `src/c/cformat.c` | 12 + 6 rows, a first-letter test | which argument is the format string |

The comment on `builtin_nonnull` says "probed from gcc itself", but no probe script exists
(checked: `bench/tools/`, `tools/`): that table has no regeneration path. Each lookup is its own
bisection or linear scan, repeated per call checked.

## Goal

One row per built-in name carries every per-name fact the front end reads from these tables. A
caller does one `bt_find` and reads columns. The three side tables, `pure_first_char`, the
bisection in `call_pure`, `builtin_is_va` and the pure generator's separate output file go.

Non-goals: `BI_ROWS`, `ev_host_fn`, `std_names` (driver macros and types, not built-ins;
dropped from AR1), the `e_call` handlers, `cbuiltin_x86.h` (target built-ins, own lowering
kind), and `bt_file_param` (`ccall.c:119`: a fourth per-name table, FILE*/struct tm*/fenv_t*
parameter kinds, 20 names; a candidate for a later column, not in this change).

Anti-goal: a hand-edited column inside a generated file. Every new column has a generator.

## Design

**Row shape.** The row struct exists three times: the anonymous struct in the generated
`cbuiltin_tab.h:11`, `BTab` (`cexpr_int.h:15`; `bt_find` casts the first to the second), and
`IaBt.bt` (`cexpr_int.h:34`; the x86 rows, built by the `IA_ROW` macros). The three new fields go
after `gnu`, numeric, in all three, so that `tests/run.sh:810` (an `awk -F'"'` reading the sig as
quote-field 6) keeps working and the x86 rows default to 0 (no pure, no nonnull, no fmt, which
is right for them):

- `pure`: 1 when gcc builds a call without side effects.
- `nonnull`: bit mask of 1-based argument positions (the table's maximum is 5).
- `fmt`: format-argument position and kind (printf, scanf, none). `strfmon` and `strftime` are
  `fmt` rows too, which also removes the second by-name special case at `cformat.c:1601-1603`
  (it sets `fmt_termonly`) and the one at `ccall.c:1826`. Whether a call takes a `va_list`
  is read from the signature (`__va_list_tag *` as last parameter; all 7 `v*` rows have it),
  not from the first letter.

The tab has non-function rows (`FILE`, `FUNCTION`, `LINE`); their columns are 0.

**Lookup semantics (the part that can change behaviour).** The old nonnull and format lookups
match a name and ignore the gnu filter of `bt_find`: `builtin_decl_ok` (`ccall.c:202`) is true
when no row is found, and the old table then applies to a plain user-declared `index`, `bcmp`,
`strdup`, `nans`, ... under `-std=c99`, where `bt_find(any=false)` returns NULL (29 of the 63
nonnull names that are tab rows have `gnu != 0`, unaudited count). So the attribute columns
are read through a lookup that ignores the gnu filter (`bt_find(c, name, true)` after stripping
a `__builtin_` prefix); the rows of the `_chk` names are `gnu = 2`, so this also keeps a plain
`__strcpy_chk` as warned as before. `call_pure` keeps `ccall_is_builtin` (a plain name must be a
library built-in in this mode) and then reads the `pure` column: unchanged filtering, since the
old table was already guarded that way. The spelling flag is derived from the name, as
`bt_for_decl` does (`ccall.c:192`): `ccall.c:567` receives the declared symbol's name, which is
usually plain (`strlen`), and only `ccall.c:1818` is `__builtin_`-only. If the old behaviour
(attribute on a plain name gcc would not treat as a built-in) is a bug, fixing it is a separate
change recorded in the plan, not slipped in here.

**Overflow names.** `{s,u}{add,sub,mul}{,l,ll}_overflow` and `add|sub|mul_overflow` (21 names)
have no tab rows and generic signatures. They stay one pattern branch (position 3 of the
`__builtin_` spelling only, at `ccall.c:1818`); rows would need a sig `bt_type` cannot parse.

**Generation.** `bench/tools/gen_builtin_attrs.py` probes gcc-13 (the default `gcc` in WSL is 15;
`gen_pure_builtins.py` already calls `gcc-13`) for the three columns. The existing generators
that read or rewrite rows (`gen_pure_builtins.py:8` parses them with a five-field regex,
`merge_builtin_pfx.py` rewrites the tab, `gen_builtin_gnu.py`/`gen_builtin_pfx.py` if they read
rows) are updated to the new row shape; `gen_pure_builtins.py` is deleted, its probe moving into
the new script. The header comment of `cbuiltin_tab.h` names the column owners.

- *pure*: today's probe (a call whose unused result warns "statement with no effect").
- *nonnull*: one translation unit per name and pointer position with a null literal there;
  gcc-13 reports `argument N null where non-null expected [-Wnonnull]` with the note
  `in a call to function '__builtin_NAME' declared 'nonnull'` (tried by hand on `strlen`,
  `memcpy`, `strcmp`, `snprintf`, `puts`, `nan`, `fputc`, `__strcpy_chk`). Varargs rows (`...`)
  need the probe's own argument construction: the pure generator skips them. One by-hand try
  of `__builtin___snprintf_chk(0,1,0,8,"x")` printed no warning for the old table's position 5
  (probe arguments may have been wrong); the probe is compared with the old table before it
  replaces it, and every difference is explained or the old entry corrected.
- *fmt*: a probe per `...`/`va_list` row is not obviously available; the plan decides between a
  `-Wformat` probe (a bad conversion at each candidate position) and seeding from the old
  tables with a check. This is the one column whose provenance is open.

**Rows missing today (measured).** The 12 `__*_chk` names of `builtin_nonnull` get rows
(`gnu = 2`, as `__builtin___strcpy_chk` spellings). `dprintf` and `vdprintf` of
`builtin_format_pos`: gcc 13 has no `__builtin_dprintf` (an implicit-declaration error, reviewer),
so the old entries apply only to plain user-declared names, and whether they matter is decided by
the equality check below and, if a corpus or test case exercises them, by a row; else they are
deleted and recorded.

## Checks that can fail

1. **Equality, per spelling and mode, before any deletion.** A throwaway program evaluates old
   function and new column on every name of the tab and of the old tables, for each spelling
   (plain, `__builtin_`, user-declared plain, implicit declaration) with gnu on and off. Every
   difference is explained as an old bug or a missed spelling; unexplained ones stop the work.
2. **Gate outputs unchanged:** `run`/`san` pass counts, verify 637/638, 289/289, 3908/3910,
   globals allowed. Weak alone: the verify counts allow failures, so a small regression in
   nonnull or format could hide in them. Check 1 and a golden test per column cover that.
3. **A golden per column** that fails with the old behaviour removed: a plain user-declared
   gnu-only name under `-std=c99` with a null argument (nonnull), a `strfmon`/`strftime` call
   (fmt), a pure built-in statement (pure).
4. **Probe against gcc:** the probe's nonnull and fmt output equals the old tables, or each
   difference is a recorded correction.
5. **Regeneration:** running `gen_builtin_attrs.py` twice leaves the file identical and equal to
   the committed tab (a script the gate can call, or a test). Weak: it shows determinism, not
   truth; check 4 supplies the truth.
6. **Work count:** callgrind before and after (current 3,819,377,416; ICOUNT A/A first for the
   tolerance). A work measure, not a correctness check; `call_pure` runs on every call, so a
   drop is expected from removing the first-character probe and the second bisection, to be
   measured, not assumed.

## Decisions

- **Nonnull provenance (decided 2026-11-04, x1).** A gcc probe is written; seeding once as a
  hand-owned column is rejected (the pattern AR1 removes).
- **`std_names`.** Dropped from AR1 as a different domain; not yet confirmed by the user.
- **Fmt provenance (open, for the plan).** See Generation.

## Not decided here

Row storage order, field widths and the exact `fmt` encoding are the plan's, provided every
check above passes.
