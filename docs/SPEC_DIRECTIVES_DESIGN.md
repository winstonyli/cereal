# Spec lines in the front end (stage 3a of `PROVER_DESIGN.md`)

Drafted 2026-11-14, rewritten after review round 4 around one placement rule (below). Decided 2026-11-14: A a1, B b1, C c1, D d1, G g1 (a spec is a pragma at the start of its body). Directive syntax and the spec language are `SPECS.md` sections 3 and 6 and are linked, not restated. This document is how the parser, checker and typed AST carry a contract (`requires`, `ensures`, `invariant`) so that the prover (stage 3b, `src/c/prove.c`) reads it as typed nodes in function scope. Decided in `PROVER_DESIGN.md` (b1, 2026-11-14): the checker's own parser reads contract expressions.

## 1. What exists (code read 2026-11-14; "reviewer" = checked by a review round, not re-read by hand)

- An unknown directive is an error (`pp.c:2666-2686`), so the bare `#requires` spelling cannot appear in any valid input. `#pragma cereal ...` is the portable spelling `SPECS.md` already gives (line 104). `pp_do_pragma` (`ppexpand.c:1154`) re-spells a pragma's raw tokens as one `TK_PRAGMA` token (`:1374-1383`; verbatim by token, a space only where `TF_SPACE`/`TF_BOL` is set, newlines collapse), expands macros only for `#pragma message` (`:1330`), and an unknown pragma ends in an `else` that warns `DW_UNKNOWN_PRAGMAS` (`:1368`, `diag_opts.def:12`).
- A `TK_PRAGMA` token is one plan item (`plan.h:30,45`), hashed by the cell cache by raw text (`cell.c:259`), printed by `-E` (`ppout.c:169-175`), replayed from `plan->pragmas` (`pp.c:3014-3027`).
- The parser's `item_pragmas` (`parse.c:1016-1075`) runs wherever a statement or declaration may start, including the first slot of any compound, and emits an `N_PRAGMA` leaf in place (`:1063`) with the right scope open (a `for` init variable and the parameters are visible). `skip_prag` (`:98-110`) makes pragmas invisible inside a declaration. At top level each pragma is its own unit (`parse_next`, `:3493-3508`, which resets `p->nodes.len` per unit). The parser has no preprocessor and no scratch cursor: tokens come from `pp_source`, `cell_source` or a `TokCursor` (`frontend.c:13-22,100,121`).
- The checker visits nodes in linear tree order, opening and closing scopes at the `N_SCOPE`/`N_SCOPE_END` markers (`check.c:609-650`), so a node typed in its place sees the names in scope there. Nodes under an `N_FUNC_DEF` before its body are read as declaration material (`tast.c:2530`, `cdecl.c:2292,3564`, `cstmt.c:1605,1637`).
- Loop nodes are read by position from both ends (reviewer: `tast.c:1488-1508`, `:2321-2332`, `cstmt_warn.c:1214`, `cstmt.c:1114-1118`); a compound's children are a free-length list, and `cstmt_warn.c:233` already skips `N_SCOPE` and `N_PRAGMA`.
- `tast.c:1686` lowers `N_PRAGMA` to a nop; `tcfg.c:401-402` drops `TO_NOP`, and an unknown op is unsupported in `tcfg.c:384-386,555` (`lunsup`), `cgx86.c:2011-2012` (`unsup`), `eval.c:2063-2070` (`UNSUP`); the verifier just breaks (`tast.c:2253`). `_Static_assert` is the precedent for a checker-typed node that lowering skips (`tast.c:1449,1721`).
- The checker re-lexes `TK_PRAGMA` text (`cpragma_apply`, `cpragma.c:594-640`, via `cdecl_pragma_visit`, `crecord.c:1489`), but its static `lex()` (`cpragma.c:44-120`) serves fixed `pack`/`GCC` shapes: names, numbers, strings, single-character punctuation; no `==`, `<=`, `&&`, `->`, character constants or keywords; no `cereal` branch (unknown names fall through silently).
- `$` lexes inside identifiers (`driver.c:23`), `==>` lexes as `==` then `>`, a directive in an inactive `#if 0` group is ignored without a diagnostic (`pp.c:2616-2619`).

## 2. Decisions (all settled 2026-11-14)

**Placement (g1, the one rule).** A spec is a statement-level `#pragma cereal requires|ensures|invariant EXPR`, and its meaning comes from where it stands:
- `requires` and `ensures` are leading statements of a function body (only other spec pragmas before them);
- `invariant` is a leading statement of a loop body, and means "holds at the loop head, before each evaluation of the test" (the position only anchors it; the prover finds the head by natural-loop analysis, which it needs anyway; for `do` the head is the body start). Several specs of one kind mean their conjunction;
- anywhere else a spec pragma is an error ("spec pragma must start a function or loop body"); this includes a spec after another pragma in the same run (`ivdep`, `unroll`), and any position the parser steps over (between a declarator and `{`, after `if (n)`, a label, in a `for` header): `adv` reports a spec pragma it skips ("must start a function body" or "loop body"; one mechanism, no per-loop special case), so a spec is never dropped silently. A spec's expression is checked as a condition (scalar, not void), and the keyword is found past comments and line splices.

The parser knows the context through a field `p->spec_ctx` (a `substatement` also serves `if`, `else` and `switch`, and `compound(p,true)` is reached from `statement`, so "loop body" cannot be inferred from `compound`): the `CK_WHILE`, `CK_DO` and `CK_FOR` cases set it immediately before their `substatement` call, the function body sets it before its single `compound(p,false)` caller (`parse.c:3205`); `compound` captures and clears it on entry (so a nested first `{` does not inherit it) and keeps the captured value as "specs allowed" until the first non-spec item, including `ivdep`/`unroll` pragmas. `item_pragmas` also runs in a struct body (`:1889`) and at top level, where "specs allowed" is false and a spec is an error. A braceless loop body never reaches `item_pragmas`; `statement` seeing a spec pragma token there reports "invariant needs a braced loop body". The pragma node is emitted with `emit(p, N_PRAGMA, tok, start, 0)` where `start` is `nmark` taken before the expression is parsed (`leaf` at `:733-736` takes its start at emit time), so the postorder child becomes a kid of the pragma, not of the compound; `decl_after_stmt` (`cstmt_warn.c:228-233`) still sees `N_PRAGMA` as the previous sibling. The expression is parsed in place, so scope is right (parameters, `for` init variables), no pending list crosses units, and no loop node changes shape. A contract before a prototype has no carrier in this cut (it waits for call support in 3b, parked).

**A (a1) spelling.** `#pragma cereal ...`, no macro expansion in the first cut: one `cereal` branch in `pp_do_pragma` ahead of the unknown-pragma warning; plan items, cell hash, `-E`, replay and the skeleton pass see nothing new. Decided against: the bare directives with expansion (a2: new plan item kind, cell hash, `-E` and replay changes, directive-table registration, macro records; nothing in S3 to S7 needs it). Parked with trigger "the first contract that needs a macro".

**B (b1) carrier.** `N_PRAGMA` with an aux kind and one expression child, lowered to a new `TO_SPEC` operation (kind in aux, one expression kid, carried verbatim and never lowered through `lx`/`lcond`, so `==>`, `&&` and `||` do not split blocks) that `tcfg` emits as an ordinary block statement; the prover finds specs by position in `Cfg` blocks: contracts lead the entry block, an invariant leads the loop's body block. Decided against: a side table on `El` (b2: an anchor from loop to head block that `Cfg` lacks); `TO_NOP` with a kid (`tcfg.c:401-402` drops it); a loop kid (round 4: loop nodes are positional).

**C (c1) scope.** Function definitions and loops. Expression forms: C expressions, `return` (the function's result, `ensures` only), `==>` (lowered to `!a || b`), `$len(p)`, and slices `p[lo:hi]` as comparison operands (`copy` needs `ensures dst[0:n] == src[0:n]`); `$len`, `return` and slices lower to `intrin` nodes (`tast_int.h`). `$old`, `$valid`, `$init`, `$all`, `$any` wait (c2: the binder and the pre-state snapshot are the two hard checker pieces and no spike needs them).

**D (d1) arithmetic.** The checker types a spec as C; the consumer reads it mathematically (`SPECS.md` 3): the prover reads `+`, `-`, `*` and comparisons as Int on spec nodes; checked-mode code generation would use overflow-detecting widening on the same nodes. Decided against: a spec mode with an unbounded integer type (d2: a new type and conversion rules for one consumer).

## 3. End-state fit

- Preprocessor: one `cereal` branch in `pp_do_pragma`.
- Parser: in `item_pragmas`, a `cereal` pragma becomes an `N_PRAGMA` with the expression parsed into a child, plus the body-start context flag and the placement diagnostics. A lexer over the pragma text, whose form the slice 1 spike decides (below). The unroll pragma's hand reader stays; folding it in is parked, not part of this plan.
- Checker: the child is typed in place (`cdecl_pragma_visit` today runs `cpragma_apply` on a leaf; it must type the child and skip a `cereal` pragma in `cpragma_apply`); a spec context does not warn about unused values or comparisons; `return`, `==>`, slices and `$len` are the only new forms. Spec names count as uses (a parameter used only in a spec is not "unused"); decided in slice 1.
- Tast and cfg: `st` (`tast.c:1686`) lowers a spec pragma to `TO_SPEC` via `fkids` and `ex(k[0], true)` (today it makes a nop); `lower` (`tcfg.c:555`, otherwise `lunsup`) gets a `TO_SPEC` case that pushes to `open_cur` like `TO_EXPRSTMT` (not the `lcond` path); explicit skip cases in `cgx86.c` and `eval.c`; `put_tree` prints it. One new operation, no table, no loop-shape change.
- Replaces and deletes nothing. `SPECS.md` section 6's `#requires` form stays design (a2, parked).
- Guard: no class of drift is removed, so none is added.

## 5. Risks

- The pragma-text lexer is settled by the slice 1 spike (2026-11-14, throwaway, about 35 lines in `item_pragmas`; works): when the pragma text starts `cereal` plus a spec keyword, lex the rest with `lexer_init_range` over its real source position (`srcmgr_ptr(p->sm, t->loc)`, as the unroll code does) using a parser-owned `ScratchCursor` (a `Parser` field, not a static), clear `TF_BOL`, `memmove` the tokens plus a `TK_EOF` sentinel into `p->toks` behind `pos`, run `parse_expr`, check that the token at `pos` is the sentinel, then emit the node. Spliced `PTok`s need only `t` (`exp`, `mloc` stay 0 meaning "spelled here"; `stdattr` is not set, harmless); `unit_end`, `base` and `fill` tolerate the splice; spliced tokens stay in `toks` (nodes index them), and `ci()` skips `TK_PRAGMA`, so they are never walked from an earlier index. Locations are exact (in the pragma line, in a header with its include chain, across a `\` continuation), and undeclared names and type errors report at the right column. Two gaps remain for slice 1: `==>` lexes as `==` `>`, so `parse_expr` needs an implication hook (a grammar operator, or fusing the two spelled-adjacent tokens); and `_Pragma("cereal ...")` points at the real `_Pragma(...)` source, so the lexed range must stop at the closing quote, with a scratch copy (as `destringize`) when the string has escapes. Top-level pragmas never reach `item_pragmas` (`parse.c:~3507`), which g1 does not need. Macros in the pragma text are not expanded (a1); a2 only if that is required.
- Spec nodes are visited by every per-expression pass (warnings, symbol index, `--dump-symbols`); the spec context must silence the warnings, and whether specs are indexed is a slice 1 decision.
- `==>` is joined from `==` and `>` with no space; `a == > b` stays an error, and a macro boundary cannot arise in a1 (no expansion).
- Braces are required on an annotated loop body, and the contract lives in the body rather than before the signature; both are conscious costs of g1.
- A `cereal` pragma inside a declaration is invisible (`skip_prag`) rather than diagnosed; this cut accepts that gap (no test claims otherwise), and the unseen spec is simply not a spec.
